# 阻抗启动与漂移审查（2026-10-23）

## 当前结论与验证边界

固定参考下的自发上升尚未在真机解决。最新执行状态、负载开关对照和后续基线计划见[独立阻抗解决记录](impedance_resolution.md)。以下内容是各阶段历史审查，历史质量、重心和“最新试验”不表示当前生效值；以 YAML 和对应 manifest 为准。

## 轴线 52 mm：本轮官方核对与配置审查

[ER3 Pro 官方硬件手册](https://static.rokae.com/Downloads/Manual/xMate%20ER3%20Pro%E7%A1%AC%E4%BB%B6%E5%AE%89%E8%A3%85%E6%89%8B%E5%86%8C.pdf) §3.2.3 定义法兰外伸法向为 +Z。用户这次假设对应 `[0,0,52] mm`，原点为机器人法兰中心。法兰随机器人旋转，不能将这个 +Z 当成世界竖直方向；相机偏置、线缆牵拉和手指姿态仍可能使真实重心偏离轴线。照片只能支持假设，不能确定 52 mm 的准确性。

本地 SDK 0.3.4 的 `data_types.h` 定义 `Load.cog` 顺序为 XYZ、单位米，因此传 `[0,0,0.052]`，无换轴或取反。保持 TCP 与质心独立。质量保持 0.9642 kg；惯量保留控制器值，零值仍未经验证。新增值也进入主遥操作启动负载，本轮只运行独立测试，不据此直接恢复完整 VR 阻抗跟随。

### 官方用法是否对应当前实现

1. **控制接口对应。** [官方笛卡尔阻抗示例](https://github.com/RokaeRobot/xCoreSDK-CPP/blob/main/example/rt/cartesian_impedance_control.cpp) 使用 `CartesianPosition` 作为目标，选择 `cartesianImpedance`；发送位姿不意味着运行的是刚性位置控制。本项目同样由 xCore 执行阻抗，没有在 Python 内实现力矩环。示例含运动轨迹、非零期望力和零刚度方向，不能直接当作静止负载试验。
2. **RT 负载不可漏设。** [官方启动异常排查](https://docs.rokae.com/docs/SDK/cpp/实时模式常见问题/cpp_rt_error_and_exception_handling/) 明确要求进入实时模式后调用 RT `setLoad`，并提醒起始位姿的新鲜度。独立程序已在 home 静止后设置 RT TCP/负载，随后启动状态接收并读取实测 TCP，回调一直返回该平衡位姿；未发送向上的轨迹。SDK Toolset 读回与 RT 接口成功仅能证明配置传递，不能证明内部补偿正确。
3. **增益并非越小越稳定。** 本轮沿用上轮 world / `[100]*6`，前三项 N/m、后三项 Nm/rad；平移 1 cm 的理想弹簧项是 1 N。较软平移可能使补偿残差更明显；转动 100 已达本地 API 上限。没有证据证明它是此次上升的根因，也不同时改增益掩盖重心变化。`mock_damping` 不是硬件阻尼；本地实时 API 没有独立笛卡尔阻尼设置。
4. **七轴与切换仍需实测。** 官方例程不指定肘角，项目沿用该行为；TCP 漂移不能全部归为零空间运动。未拿到控制器内部动力学和完整成功 RL 工程，不能断言所有版本行为等价。当前参考在 `startMove` 前获取；切换期间是否存在补偿偏差仍需诊断，不能通过不断追随漂移更新参考来隐藏问题。
5. **不要移植 Franka 力矩公式到 ROKAE 原生阻抗输出。** [Franka 官方示例](https://github.com/frankarobotics/libfranka/blob/main/examples/cartesian_impedance_control.cpp) 在主机计算弹簧/阻尼和模型项后输出关节力矩；本项目输出平衡位姿，由 ROKAE 原生模式处理。两者实现层级不同，不能重复叠加补偿，也不能拿 Franka 阻尼数值直接填入当前 SDK。
6. **版本边界。** 当前运行库 0.3.4 / 控制器 2.3.2；在线文档为 0.7.x，调用均与本地头文件交叉核对。[官方变更记录](https://github.com/RokaeRobot/xCoreSDK-CPP/blob/main/CHANGELOG.md) 给出 0.7.0 对 xCore 3.2.0 的兼容要求，不能仅为试漂移替换动态库。最新示例注册回调后启动模式的顺序已在本项目采用。

### Quest3 是否必须用阻抗

不必须。Quest3 负责测量手腕/手指；映射层产生机器人参考，执行层才选择位置或阻抗。项目 `control.controller` 默认仍是 `position`，`--arm-control impedance` 是显式选择。主机位置路线经 IK/关节流控制；阻抗路线将有界 TCP 目标作为移动平衡点。二者都可以采集状态/动作；阻抗下实际 TCP 与平衡目标可能不同，数据中必须保留两者语义，不能把平衡目标当作实际位置。

[Open-Teach Franka 接口](https://github.com/aadhithya14/Open-Teach/blob/main/openteach/robot/franka.py) 将上层位姿调用交给机器人控制适配层，亦说明 VR 输入与底层执行应分层。它不是 ROKAE 兼容性证明。需要接触柔顺时阻抗是一条适用路线，但“手碰障碍必不下电”不是阻抗保证；力矩、关节和异常保护仍然存在。

## 控制与数据路径

- 统一 YAML → Python 参数校验与 mm/m 转换（仅实验 CLI 输入为 mm）→ 原生参数/桥接配置 → SDK Toolset 质量、重心写入与读回 → RT setLoad；两次赋值不是两次质量叠加。RT 接口无独立动力学读回，不能声称内部实际补偿已核实。
- 独立试验：检查型号/静止/软限位/零 TCP → 设置负载 → automatic/RtCommand/上电 → 位置控制回 home → 连续静止 0.5 秒 → 显式 RT TCP → 力控坐标/负载/刚度/零期望力/滤波 → 读取实时初始 TCP 和关节 → 注册回调 → startMove → startLoop。
- 固定参考回调不使用 Quest、主机 IK 或 Python 调度；每周期返回同一初始实测 TCP，不把实际漂移追认为新平衡点。SDK 行优先矩阵的平移为索引 3/7/11。
- 实测反馈 → C++ 启动关节偏移/速度/TCP 范围检查 → setFinished → stopMove/stopLoop → 下电读回 → 保存轨迹。反馈读取失败也终止。
- 遥操作路径：任务参数 → 控制器 spec → Python driver → C++ 配置 → 同样的负载设置。参考来自控制核心；阻抗启动先 HOLD，键盘 e 后才更新 VR 参考。HOLD 固定平衡点，不是位置控制抱死。

## 本轮修正

1. 独立试验将 `setControlLoop` 移到 `startMove` 之前，符合新版官方示例，避免启动后才注册回调。
2. 独立试验和主驱动均显式调用 RT `setEndEffectorFrame`，使用已有核对的 TCP，在读取实时参考之前执行。独立试验只接受单位 TCP；主驱动保留已有工具变换。不再隐含假设 SDK Toolset 必然同步了实时 TCP。尚无证据表明此前确实残留错误 TCP。
3. 独立试验在启动前记录控制器告警，与结束后的日志分开，便于识别旧告警；不声称最多十条日志是完整事件档案。
4. 修正离线分析的关节位移基准：优先使用 `initial_impedance_q`，而非首帧（首帧之前可能已发生运动）。旧记录缺该字段时显式标明回退来源。
5. 增加真实 C++ 护栏轨迹回放，以及离线轴变换和理想弹簧检查。没有增加真机批量遍历负载入口。

## safety、刚度、阻尼、坐标

- `hold_zlgonasd`：0.288287 s，上升 9.395 mm，峰值关节速度 0.09425 rad/s。
- `hold_letxbxvg`：0.343178 s，上升 9.025 mm，峰值关节速度 0.07645 rad/s。
- 两者速度低于 0.15 rad/s；J4 相对启动参考超过 0.02 rad。两次位移相似是相同护栏截断，不能推断自然平衡点。
- 实际 SDK 0.3.4 头文件允许刚度上限 [1500,1500,1500,100,100,100]，当前 [300,300,300,15,15,15] 在范围内；“范围内”不代表在这台硬件上稳定。当前记录不足以认定高刚度振荡。
- 真机没有应用 `mock_damping`；它只属于离线模型。当前本地实时 API 未暴露独立笛卡尔阻尼设定。30 Hz 是滤波参数，不是阻尼比。
- 平移和旋转刚度各自各向同性、期望力为零；仅旋转力控轴方向不会改变理想的这组刚度。控制点平移、负载坐标错用、RT 工具状态不一致是不同问题。
- 7 轴阻抗没有强制 elbow 参考，存在冗余运动可能；但观测到 TCP 位移，不能把它归结为纯零空间运动。未凭猜测新增零空间参数。
- 当前 tool2 的 TCP 标定定义和零惯量仍未独立核实；照片不能替代坐标标定。

## RobotAssist 程序截图与工具表实读对照

用户新增截图 `rokae/media/code.png` 的程序明确为：

```text
GLOBAL PROC main()
FcInit tool1,wobj0,0
SetControlType 1
SetCartCtrlStiffVec 100,100,100,100,100,100
FcStart
wait 100
FcStop
ENDPROC
```

据官方 FcInit 定义，第三项 0 指世界方向，力控原点为工具 TCP；SetControlType 1 是笛卡尔阻抗。截图成功路径使用 tool1，不是 tool2。工具表截图 tool1 显示约 0.96 kg、[-29.69,21.37,-34.89] mm；tool2 显示约 0.97 kg、[-26.90,23.48,-41.46] mm。截图是舍入显示，不能用作 tool1 的精确标定文件。两者重心差约 7.44 mm，并非轴序互换。

与独立 RT 测试的主要差异：RL 使用控制器内 FcInit/FcStart（无主机参考流），世界方向、tool1、刚度 [100,100,100,100,100,100]；独立 SDK 使用 RT cartesianImpedance、工具方向、tool2 数值负载、刚度 [300,300,300,15,15,15]。平移刚度 RL 为 RT 的 1/3，转动刚度为 6.67 倍。0.3.4 不提供后续版本的完整 NRT forceControl API，不能把主机 RT 接口假称为 RL 同路径。各向同性刚度下单纯世界/工具轴旋转不能解释全部差异，但 TCP 原点和实际工具定义仍必须一致。

hold_qj630rs6 末帧相对参考转角约 0.8996 度；理想线性转动弹簧在该角度的力矩幅值 K=15 时约 0.236 Nm，K=100 时约 1.570 Nm。此计算只量化参数差异，不代表真实控制器输出，也不证明提高转动刚度即可稳定。

## 方向不对称与软件质量试验（2026-10-24，新增证据）

用户报告 0.3642 kg 时左右/向下推可回弹，向上推不回；0.0642 kg 感觉改善但仍不完全回弹。八轮新 trace 中 sent_tcp 均与固定参考一致，SDK pos_c 均为有效位姿，距参考的最大平移差仅 0.0008593 mm。这支持目标发送与 SDK 指令反馈保持固定，不能据此证明内部补偿和力矩输出正确。此前“pos_c 现场支持未验证”的限制已由这些新记录部分消除；字段含义仍仅限 SDK 指令反馈。全部八轮平移刚度仍为 100 N/m，并未运行 spring-check 300 N/m 对照。

推断：向上的等效残余力/力矩与摩擦能解释方向不对称。在局部一维模型中，取向上为正，F = -K(z-z0) - D*v + b；b>0 时向上偏移后的向下恢复力减弱，向下偏移后的向上恢复力增强。摩擦还允许一个停止区间，而不是唯一精确回位。此为解释模型，不是对实际 b、K、D 的辨识；未记录精确松手时刻和独立外力。

0.0642 kg 不能作为完整组件的物理质量。0.3642→0.0642 kg 的 0.3 kg 差约对应 2.94 N 重力项；在理想 100 N/m 模型中可对应 29.4 mm 平衡位移量级，但真实机器人有姿态相关的关节映射、摩擦和模型误差，不能用这个数反算已证实的零偏。减小软件质量可能在一个姿态抵消别的错误。左右有恢复和 pos_c 固定使“误用纯自由拖动/目标跟随”更不符合当前证据，仍不能排除控制器内部力控配置问题。

修正顺序：

1. 停止以继续减质量或增加位移范围作为负载辨识；称量完整组件，核实辨识重心原始坐标和实际启用工具。保留当前试验记录，不自动把 YAML 改回约 0.96 kg 后重启——该值已有启动漂移证据。
2. RobotAssist/RL 与 SDK 必须使用同一真实负载、CoM、TCP、力控坐标、home 和刚度作对照。之前 tool1/RL 的成功不能直接替代当前参数验证。若 RL 正常、SDK 异常，优先核对 2.3.2 的 RT 负载及力控初始化，并将记录交厂商核实；API 赋值没有显式相加，不等于已证明固件内部绝无重复补偿。
3. 若两条路径在相同参数下都不对称，按匹配控制器的官方流程检查本体型号/安装方向/动力学参数和关节力矩传感器零偏。传感器零偏校准与负载辨识不同；带载是否允许、所需机械姿态及卸载条件须由该机型文档/厂商确认，不通过随意归零消除重力读数。
4. 补偿核实后再调刚度和接触动作；spring-check 是增益对照而非负载修复。软阻抗受摩擦影响可能有毫米级回位误差，不能以百分之百数学回位作为唯一指标，更不能用低软件质量直接验收遥操作/策略部署。

[官方实时模式排障](https://docs.rokae.com/docs/SDK/cpp/实时模式常见问题/cpp_rt_error_and_exception_handling/) 要求进入 RT 后设置对应的 setLoad，并区分模型库和力控接口。[官方控制器故障排查](https://docs.rokae.com/docs/xCore/18-故障排查/) 的 10040 排查项涉及工具、坐标、机型/RD 参数及传感器零点。网页当前分别为 SDK 0.7.x 与 xCore 4.0，可作排查方向，不代表当前 2.3.2 可直接使用其新接口或校准步骤；本轮也未发现/声称出现了 10040 报错。
