## 实现范围

新增 `rokae/examples/06_recover_soft_limits.py`，提供默认只读检查和显式 `--execute` / `RECOVER` 确认。原生 `recover_disabled_soft_limits()` 与离线规划共用同一校验函数，独立于初始化、实时控制、相机及数据采集。现有 `--recover-joint-limits` 行为保留，只有初始限位关闭时的错误提示改为指向新入口。

输入为操作者确认的当前关节、原软限位及回退余量；执行前、模式切换后、上电后重新核对。只接受单轴轻微超限（<=1°）；Jog 速率固定 1%，余量默认 0.5°，显式参数限于 0.5–10°。不关闭限位、不重写限位值、不清除报警、不自动进入 home 或遥操作。停止后在下电/手动状态恢复原限位并回读；失败时报告未确认状态。

## Review 发现及处理

- 原 `MoveAbsJ` 恢复流程与官方建议的手动 Jog 不一致：新增独立 Jog 入口，不放开原初始化的保护检查；文档不再将旧流程推荐为已验证的恢复手段。
- 默认回到边界内 0.5° 仍位于 init 的 0.15 rad 保护区：增加显式 `--clearance-deg 10`，并针对计划中全部关节的最小余量显示提醒。给定日志的 J6 对应目标约 105°，只属于离线计算。
- 确认后或上电过程中可能发生位置、模式、限位变化：执行前多次复查，出现变化拒绝 Jog。
- Jog 步长使用度而关节反馈使用弧度：在原生接口边界换算；目标轴索引从零开始。
- 即使 Jog 已自行停止仍需 `stop()`：成功、异常和信号中断后的收尾均进入停止/下电/尝试恢复流程。恢复失败另行请求下电，保留原始错误原因，不伪报恢复成功。
- 新入口不进入自动模式、不调用实时控制、不改变现有遥操作或数据格式，不在 1 kHz 控制回调中添加逻辑。

## 现场上电失败反馈后的修正

用户现场日志：控制器 2.3.2、xMatePro3、off/manual/idle、软限位已关闭，执行在 `setPowerState(true)` 返回“上下电失败”；因此该次未发送 `startJog()`。后续仍超限导致无法恢复限位，是该失败的后果，不能误报为新的运动故障。现场成功恢复尚未验证。

发现上一版遗漏了 SDK 0.3.4 `robot.h` 第 69 行的明确条件：只有无外接使能开关或示教器的机器人才能通过 SDK 手动上电。通用“上下电失败”本身不能确认现场是否连接了这些装置，也不能排除安全门、急停和其他控制器报警。

修正后的入口默认 `--manual-power-source operator`：不请求 SDK 上电；在停止/下电/手动后提示现场人员，在 30 秒内操作物理使能，并在 Jog 停止后释放使能以完成下电。显式 `sdk` 路径仅适用于符合官方条件的设备。保持原有边界、单轴、确认、状态复查及限位回读保护；不引入自动模式、IO 仿真、使能绕过或报警自动清除。

新增只读 `get_controller_logs(count=10)`，由 SDK `queryControllerLog` 返回 ID、时间、内容及处理建议；`01_read_state.py --controller-logs` 可独立查询。恢复失败后查询最近日志，查询失败不覆盖原异常。恢复错误优先保留原始原因，并区分是否请求过 Jog、是否回读确认下电与限位恢复是否确认。

x86_64 原生重新构建通过；恢复入口及原生加载回归共 46 项离线测试通过。本轮全套结果为 178 passed、1 failed、9 subtests passed（10.91 s）；唯一失败仍为原有 init 速度断言。模块依赖、语法、147 个本地文档引用检查无错误。新增测试涵盖默认/显式上电来源传递、日志展示、日志读取失败保留原异常、日志查询参数范围和未连接时拒绝查询。这些不等同于真实手动上电、Jog、物理使能释放或通讯故障恢复的验证。
